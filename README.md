# Beautiful Blinds & Shades landing page

This landing page has its own GitHub repository: [cody-del/beautifullanding](https://github.com/cody-del/beautifullanding), on branch `main`. Keep its source and assets separate from the main website repository, `cody-del/BEAUTIFUL`. The existing Sites publication is configured by `.openai/hosting.json`; `dist/` contains the complete static landing page.

Netlify serves this landing page at `https://go.beautifulblindsandshades.com/`. The root `netlify.toml` sets the repository base to `.` and the publish directory to `dist`, with no build command because the complete static output is checked in. Publishing the repository root causes the domain root to return 404 while the page is only available under `/dist/`. After content edits, regenerate `dist/` before pushing to `main`.

The October 20 lead-delivery revision sends the quote form to Beautiful Blinds & Shades' GoHighLevel sub-account, the same way cody-del/Howards-landing-new sends Howard's leads. `form.js` posts JSON to `/api/consultation`, the Netlify function in `netlify/functions/consultation.mjs`, which upserts the contact through GHL's `contacts/upsert` API with the single tag `google_landing_page` and the source "Google Ads Landing Page (go.beautifulblindsandshades.com)". The full name is split into first name and last name, and the phone number is sent as +1 and ten digits. GHL's "Form Submission bbs" workflow triggers on that tag. It creates the opportunity and sends the alerts, so renaming the tag detaches new leads from it. The function accepts only same-origin JSON POSTs of at most 8 KB. It refuses submissions that fill the hidden `website` field, arrive less than 3 seconds after the page loads, or fail the name, phone, and email checks. It allows at most 5 leads per visitor per 15 minutes. Lead details go only in the request body, never in a URL, and logs record only the HTTP status or error type. The function needs two Netlify environment variables: `GHL_PRIVATE_TOKEN`, a private integration token for the sub-account with contact write access (`GHL_API_KEY` is accepted as a fallback), and `GHL_LOCATION_ID`. Without them, the form tells the visitor to call. The page reports success only after GHL returns a contact id. Only then does it call `reportLeadConversion()`, which sets enhanced-conversion email and phone and fires the Submit Lead Forms conversion with transaction id `lead_<contactId>`, so a repeat submission by the same person counts once. It then shows a thank-you card. Failures keep the form and show the phone number. The Netlify build now runs the tests, so a failing test stops the deploy: `node --test tests/owner-video.test.cjs tests/consultation.test.mjs tests/consultation-http.test.mjs tests/form.test.cjs`. No live test lead has been sent.

The October 27 SMS consent revision adds one optional, unticked A2P 10DLC opt-in above the quote button: "Text messages (optional)". Its wording follows the SMS Terms on beautifulblindsandshades.com/terms-of-service, which cover service messages only (consultations, appointments, estimates, scheduling, project updates and customer service). So there is no marketing opt-in. It names Beautiful Blinds & Shades and states the message frequency, data rates, STOP, HELP, and that consent is not a condition of purchase. `form.js` sends it as the boolean `smsOptIn`. A ticked box adds the GHL tag `sms-transactional-opt-in` next to `google_landing_page`, the same tag Shenandoah's and Sky Window's A2P forms use. A phone number alone is not consent: any GHL step that texts these leads must check for that tag. Below the button, the form says submitting agrees to the Privacy Policy and Terms of Service and that SMS consent is not shared with third parties. The footer links both pages as well.

`/privacy-policy/` and `/terms-of-service/` are copies of the main site's pages, so those links stay on this domain. The main site owns the wording: the copies keep its text word for word and drop only Webflow's markup. The script refuses anything but text, headings, lists, line breaks and links, and the build does not run it, so a main-site outage can't stop a deploy.
